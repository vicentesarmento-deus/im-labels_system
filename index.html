Labels prototypes

Interactive prototypes for the labels experience on an evaluation post. The question they exist to answer: which interaction model works better — resolving label changes in place on the page, or resolving them inside a modal? Handling a second person editing the same post is one of the tests that separates the two, not the goal in itself.

Open one and use it as you normally would — the dark bar at the top is prototype scaffolding, not product UI.

Current — for interviews

v3Save flow — in place vs modal

The two candidate interaction models, side by side. V1 resolves every action in place on the page, so the card itself is the editor; V2 resolves everything inside an “Edit labels” modal.

Both share the same rules underneath — an explicit save step, visible authorship on each label, and a switch to simulate someone else editing the same post — so anything a participant prefers comes from the interaction model, not from a feature one version has and the other lacks.

v2Input variants a–h

The exploration that narrowed the field: eight ways (a–h) of adding and managing labels, from fully inline to fully modal. v3 takes the two ends of that range and makes them comparable.
